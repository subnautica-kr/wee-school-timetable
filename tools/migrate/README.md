# 옛 자료 이전 도구

옛 앱 작업 파일(`*.shiftgrid.json`)이나 새 앱 백업 파일을 읽어, 돌고 있는 새 앱의 한 기관에 넣는다.
앱 화면이 쓰는 HTTP 길로만 넣는다 — DB 를 직접 만지지 않는다. 기관관리자 계정이 있어야 한다.

## 1. 먼저 미리보기 (아무것도 안 넣는다)

```bash
export MIGRATE_LOGIN=관리자아이디
node tools/migrate/index.js preview ./옛파일.shiftgrid.json --url https://앱주소 --org 3
```

- 비밀번호는 물어볼 때 친다(화면에 안 보인다). 환경변수 `MIGRATE_PASSWORD` 로 줘도 된다 — 어느 쪽이든 화면·결과 파일에 안 적는다.
- 표 칸: 항목 · 원본 · 이미 있음 · 새로 넣음 · 못 옮김. 아래에 「못 옮기는 것」이 이유와 함께 나온다.

## 2. 넣기

```bash
node tools/migrate/index.js apply ./옛파일.shiftgrid.json --url https://앱주소 --org 3 --out ./이전결과.json
```

- `--out` 은 꼭 있어야 한다. 새로 만든 계정의 임시 비밀번호는 이 파일에만 적힌다(화면엔 개수만). 나눠 준 뒤 파일은 지운다.
- 짜 둔 시간표는 **시안**으로만 들어간다. 확정은 앱에서 다시 한다.
- 같은 명령을 두 번 돌려도 이미 있는 반·시수표 줄·같은 이름 시간표는 건너뛴다.

## 선택

| 인자 | 뜻 |
|---|---|
| `--create-missing` | 옛 파일의 교사·과목이 명단·교과 목록에 없으면 새로 만든다(없으면 「못 옮긴 것」으로만). 반은 늘 만든다. |
| `--login-prefix 앞말-` | 새로 만드는 계정 로그인 ID 앞에 붙인다. 백업 파일을 다른 기관에 되넣을 때 ID 가 겹치지 않게. |

## 맞추는 규칙

- 교사: 옛 파일은 이름(같은 이름이 둘이면 못 가름) · 백업은 로그인 ID.
- 과목: 이름, 옛 파일은 그다음 줄임말(예: 「창체」 → 창의적체험활동). 교과가 하나도 없는 기관은 기본 교과 14개가 먼저 생긴다.
- 반: 학년·반 번호. 담임·학생 수는 비어 있는 칸만 채운다.
- 교시: 원본에 있는 학년만 덮는다(요일별 교시 포함). 다른 학년은 그대로.

## 안 옮기는 것

옛 파일의 주간 금지칸·날짜 차단·규칙·보드·교사 등급 · 백업의 지난 학기·보결·특별실 예약·근태·감사 기록·기관 설정.
모두 「못 옮긴 것」 목록에 이름으로 나온다.
